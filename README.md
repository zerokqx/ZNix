# ZNix

Персональная конфигурация NixOS и Home Manager для трёх машин x86_64-linux.
Рабочее окружение: Hyprland, Caelestia Shell, Fish и Nixvim.
Dank Material Shell сохранён как резервный вариант.
Основная версия системы — NixOS 26.05; зависимости закреплены в `flake.lock`.

| Хост flake | Имя системы    | Профили                                                             |
| ---------- | -------------- | ------------------------------------------------------------------- |
| `desktop`  | `nixos-pc`     | workstation + development + personal                                |
| `laptop`   | `nixos-laptop` | workstation + development + personal                                |
| `noop`     | `nixos`        | workstation + development + personal + дополнения Home Manager noop |

`flake.nix` использует flake-parts. Системы и самостоятельные конфигурации
Home Manager явно зарегистрированы в `hosts/default.nix`. Форматирование, среда разработки, VM-тест и проверки определены через
`perSystem` в `flake/`. Отдельных приложений для `nix run` и установщика для
сторонних пользователей нет; Nixvim входит в личную конфигурацию Home Manager.
Каждый хост явно подключает базу, профили и своё оборудование. Общие системные
модули находятся в `core/` и `configs/`, пользовательские настройки — в `home/`,
общие модули Home Manager и политика пакетов — в `lib/`.

## Проверка и сборка

```sh
nix develop -c bash
nix fmt -- flake.nix hosts/default.nix
./scripts/check.sh all
nix flake check --no-build --no-update-lock-file
nix flake check --no-update-lock-file
./scripts/rebuild.sh build desktop
```

Для проверки всей серии изменений укажите `check.sh all --base <коммит>`.
Новые файлы, на которые ссылается flake, добавляйте в Git точными путями после
проверки содержимого. Скрипты пересборки сами ничего не добавляют в индекс.

Общая команда `rebuild` по умолчанию только собирает систему. Команды devenv
`rebuild-desktop`, `rebuild-laptop` и `rebuild-noop` применяют конфигурацию;
варианты `-test` тоже меняют работающую систему. Используйте их осознанно.
Без указания хоста скрипт ищет единственное соответствие текущему имени машины.
Успешная сборка не означает применение конфигурации или проверку оборудования.

```sh
python3 scripts/install-skills.py --environment codex

```

Codex читает `.agents/skills` напрямую. Для Claude создаются относительные ссылки
на каждый skill. Повторная установка безопасна и останавливается при конфликте.
Глобальные настройки агентов не меняются.

## Добавление хоста

Создайте модуль в `hosts/<имя>/` с явными imports оборудования, базы и выбранных
профилей. Зарегистрируйте его в `hosts/default.nix` через `nixpkgs.lib.nixosSystem`.
Самостоятельную конфигурацию Home Manager при необходимости добавьте через
локальный `mkHome`. Подробности — в [описании архитектуры](docs/architecture.md).

UUID дисков, параметры возобновления из гибернации и мониторы относятся к
конкретной машине. Для другой архитектуры процессора отдельно проверяйте
совместимость пакетов. Применение конфигурации и разрушительные операции
требуют явного разрешения владельца.

## Nixvim: аудит и оптимизация

Итерация `refactor/nixvim-performance-modernization`, исходная точка `ef9a24e`.
Nixvim остаётся личным модулем Home Manager с явными imports. Публичные
`nix run` outputs не возвращены. `flake.lock`, тема TokyoNight, основные клавиши,
Blink, Snacks и Mini сохранены.

### Что изменилось

- Rust-тесты ищутся запросом Treesitter вместо рекурсивного обхода всех узлов
  из Lua. Результат кешируется до изменения текста. Сворачивание учитывает
  конкретное окно, повторные события и переключение буфера до отложенного вызова.
  Распознаются модули `test/tests`, точный `#[cfg(test)]` и атрибуты
  `test/rstest/test_case/quickcheck/proptest`, включая квалифицированные имена.
  Случайные подстроки вроде `#[contest]` больше не считаются тестами.
- Большие буферы дополнительно исключены из миникарты, направляющих,
  Git-декораций и автоматического включения inlay hints. Существующий порог
  Snacks и отключение подсветки/автодополнения сохранены.
- Автосохранение проверяет пригодность буфера до создания таймера и отменяет
  таймер при выгрузке. Запись остаётся синхронной, задержки не менялись.
  Исправлена гонка восстановления раскладки при быстрых переходах Insert mode.
- Настройки vtsls больше не перекрывают подключение `@vue/typescript-plugin`.
  Lua, JSON и YAML используют структуру настроек закреплённого Nixvim.
  Удалены 18 повторных объявлений пакетов LSP и неиспользуемая настройка
  Blink buffer source. Сами серверы предоставляет Nixvim; это не удаление LSP.
- Treesitter использует поддерживаемые параметры `highlight`/`indent` и явный
  набор из 60 грамматик вместо 326. Включены языки конфигурации, запросов и
  вложенных фрагментов. Произвольный язык внутри Markdown может потребовать
  добавления грамматики в `config.nix`; сам Markdown продолжает работать.
- Gitsigns использует `nav_hunk`; в diff-окне `]c/[c` сохраняют нативные переходы.
  Справка по клавишам имеет один обработчик и берётся из runtime сборки.
  Цветные иконки таблайна обрабатываются одним проходом по видимым вкладкам.
- Добавлены изолированный benchmark, функциональные Lua-проверки и
  [skill Nixvim](.agents/skills/nixvim/SKILL.md). В этой итерации установщик был расширен до восьми skills; текущий набор
  с desktop и stylix содержит десять.

### Измерения

Обе сборки используют один `neovim-unwrapped-0.12.4`, одинаковые fixtures и
семь повторов. Терминальные измерения выполнены в PTY 100×32 с ответами на
запросы терминала. `cold` означает новые HOME/XDG-каталоги; кеш ОС не очищался.
Прогрев перед серией `warm` исключён из результата. В таблице медианы.

| Сценарий                                 |            До |         После |
| ---------------------------------------- | ------------: | ------------: |
| Headless, cold                           |      88,70 мс |      91,16 мс |
| Headless, warm                           |      76,05 мс |      73,99 мс |
| Терминал, cold                           |      96,71 мс |      89,33 мс |
| Терминал, warm                           |      78,74 мс |      72,04 мс |
| Rust-тесты: первый вызов после изменения |      43,30 мс |      18,36 мс |
| Rust-тесты: повторный вызов              |      39,31 мс |       0,22 мс |
| Открытие и перерисовка небольшого Rust   |     130,28 мс |     126,94 мс |
| Открытие Rust, 1 500 987 байт            |     114,99 мс |     115,67 мс |
| Открытие небольшого JSON                 |      18,05 мс |      15,30 мс |
| Открытие JSON, 2 371 338 байт            |      21,80 мс |      20,94 мс |
| Переключение буфера и перерисовка        |       2,32 мс |       2,30 мс |
| RSS после сценария открытия файлов       |    42 572 КиБ |    42 756 КиБ |
| Полное замыкание Nix, NAR-байты          | 6 378 431 120 | 6 167 189 992 |

Первое сворачивание ускорилось на 57,6%, повторное — на 99,4%.
Диапазоны первого вызова: 31,40–45,98 → 14,80–21,06 мс; повторного:
38,44–42,75 → 0,16–0,31 мс. Здесь эффект превышает разброс.
Диапазоны прогретого терминального запуска пересекаются:
73,73–92,51 → 69,60–81,54 мс. Считать это доказательством устойчивого
ускорения запуска нельзя. Память и открытие больших файлов практически
не изменились. Первый Rust-файл оплачивает начальную загрузку подсистем;
сравнение маленького и большого файла внутри одной серии не характеризует
масштабирование. Отложенное автосворачивание не входит в `edit+redraw`;
оно проверяется отдельно, ручное сворачивание измеряется в свежем процессе.

Замыкание уменьшилось на 211 241 128 байт (3,3%). Его основную часть по-прежнему
занимают языковые серверы и инструменты. Это размер NAR всех зависимостей,
а не трафик загрузки и не место, освобождённое на диске. Сборка использовала
доступные substitutes и локально собрала конфигурацию, обёртку и набор queries.
Для этой локальной сборки Nix запланировал 75 derivations и загрузку 89 путей
(100,6 МиБ скачивания, 330,6 МиБ после распаковки). Исходная сборка уже
находилась в store, поэтому сравнивать эти числа как ускорение сборки нельзя.
Время сборки с нуля и cache hit rate не измерялись. Изменение доверенных кешей
или объединение nixpkgs Nixvim с системным input для этой задачи не требуется.

Дополнительно выполнены три парных прогона LSP с чередованием порядка сборок.
Для каждого языка запускался свежий редактор с отдельными HOME/XDG, но
прогретым кешем ОС. Проекты небольшие, без `node_modules`. Измеряется время
от открытия файла до подключения нужных клиентов или первой диагностики.

| Сценарий LSP                 | Медиана до | Медиана после |
| ---------------------------- | ---------: | ------------: |
| Подключение CSSLS            |  151,65 мс |     150,35 мс |
| Первый запрос CSS completion |   29,55 мс |      34,82 мс |
| Подключение Pyright и Ruff   |  229,88 мс |     216,69 мс |
| Первая диагностика Ruff F401 |   87,31 мс |      84,38 мс |
| Подключение Vue и vtsls      |  563,29 мс |     591,45 мс |

Запрос completion измеряет ответ сервера, без интерфейса Blink. Vue после
исправления подключает ранее отсутствовавший TypeScript-плагин. Результаты
смешанные, трёх прогонов недостаточно для вывода об общем ускорении LSP.
Например, диапазон Vue составляет 527,91–688,62 → 563,35–675,77 мс,
CSS completion — 22,46–30,95 → 28,89–36,84 мс.

### Проверки и воспроизведение

Команды сборки, изоляции HOME/XDG и запуска проверок описаны в
[skill Nixvim](.agents/skills/nixvim/SKILL.md).
Скрипт `scripts/benchmark-nixvim.py` принимает путь к собранному `bin/nvim`,
новый каталог результатов и необязательный `--runs`. Он сохраняет сырые
traces, журналы, fixtures и `results.json`. Не запускайте параллельно с ним
сборки или языковые серверы другого теста.

Реальный LSP проверяется отдельно от startup. CSSLS должен возвращать `color`
со snippet capability, Ruff — диагностику и отключённый hover, Pyright —
подключение, Vue/vtsls — подключение с `@vue/typescript-plugin`. Остальные
серверы требуют отдельных проектов и не считаются проверенными этим тестом.
Замеры PTY не измеряют задержку физических клавиш, GPU/терминальный рендеринг,
completion на большом рабочем проекте или производительность всех серверов.
Применение Home Manager/NixOS и проверка реальной раскладки Hyprland не выполняются;
гонка раскладки проверяется с подменённым вызовом процесса.

Подтверждены сборка редактора и `programs.nixvim.build.test`, все три
Lua-сценария, 22 теста инструментов, форматирование/ShellCheck и evaluation
трёх NixOS-хостов и трёх Home Manager outputs. `nix flake check` также завершился
успешно со сборкой проверок. Независимая проверка подтвердила
сохранение таблайна, справки, Conform defaults, переходов Git/diff, JSONC и
возврата к обычному Rust-буферу после большого файла. Полные системы не
собирались и не запускались. Сохраняется прежнее предупреждение Home Manager
о `nixpkgs.config/overlays` при `useGlobalPkgs`; оно не относится к Nixvim и
требует отдельной правки общего управления пакетами.

## Caelestia, Stylix и графический вход

Основная оболочка — **Caelestia Shell** (`caelestia-dots/shell`), резервная —
Dank Material Shell. Hyprland и сессия UWSM сохранены. Оболочку выбирает
`programs.caelestia.enable` в `home/zerokqx/desktop.nix`; отдельного desktop
framework нет. Основные сочетания клавиш выбирают команды активной оболочки.
DMS, его input, плагины, настройки и команды остаются в репозитории.

Для возврата к DMS задайте в Home Manager:

```nix
programs.caelestia.enable = false;
```

DMS включится по умолчанию. Одновременное включение обеих оболочек запрещено
assertion. Запуск выбранной оболочки происходит через `exec-once`, а не второй
systemd-сервис. Для Caelestia отдельно запускаются polkit agent и clipboard
history; DMS использует свои реализации. Caelestia обслуживает панель,
уведомления, OSD и обои. Автоматические idle/DPMS/suspend таймеры не добавлены.
Screen sharing, XDG portals, мониторы и существующие правила окон сохранены.

### Общая тема и локальный target

`lib/stylix-theme.nix` содержит общие исходные настройки Tokyo Night Dark,
SN Pro, FiraCode Nerd Font и размеров текста. Системный Stylix передаёт
палитру, шрифты, прозрачность и изображение встроенному Home Manager;
standalone Home Manager получает те же defaults. Для согласованной смены
темы входа и оболочки задавайте `stylix.base16Scheme`, `stylix.fonts`,
`stylix.opacity` и `stylix.image` на системном уровне. Пользовательские
Home Manager overrides намеренно могут отличаться от системного оформления.

Локальный target — `home/zerokqx/znix/stylix-celestia.nix`:

```nix
stylix.targets.celestia.enable = true;
# Отдельная роль: RRGGBB без #.
stylix.targets.celestia.colours.primary = "7aa2f7";
# Обычные настройки имеют приоритет над defaults target.
programs.caelestia.settings.appearance.font.body.medium.size = 14;
```

Target использует `config.lib.stylix.mkEnableTarget` и включается только при
активных Stylix, target и Caelestia. `stylix.enable = false`,
`stylix.targets.celestia.enable = false` или выбор DMS отключают его настройки
и окружение. `mkTarget` вне autoload-контекста Stylix не вызывается.

Из Base16 декларативно генерируется JSON со всеми цветовыми ролями,
которые использует закреплённая Caelestia. Фоны и поверхности используют
base00–base02, текст — base05/base06, вторичные элементы и границы — base03/base04;
акценты — base0D/base0C/base0E, ошибка — base08, успех — base0B,
терминальный жёлтый — base0A. Дополнительные роли задаются через стандартные
приоритеты Nix, отдельной синхронизации shell-скриптом нет.

Upstream читает цвета из изменяемого CLI state и не предоставляет подходящего
параметра для внешней схемы. Поэтому локальный `caelestia-stylix.patch` добавляет
чтение `CAELESTIA_STYLIX_SCHEME` и `CAELESTIA_STYLIX_WALLPAPER`.
Патч применяется при сборке только пакета с включённым target; Nix store
не редактируется, постоянного fork и фонового watcher нет. Выбор схемы в GUI
при управлении Stylix ограничен, чтобы не предлагать неработающие изменения.
Обычные настройки CLI пользователя не заменяются декларативными ссылками
на файлы его состояния.

Шрифты и размеры передаются через официальные `programs.caelestia.settings`;
пакеты шрифтов добавлены в fontconfig оболочки, включая сохранение её icon fonts.
`stylix.opacity.desktop` управляет базовой поверхностью,
`stylix.opacity.popups` — слоями. Не все компоненты upstream имеют независимые
параметры прозрачности или отдельную роль предупреждения.
При заданном `stylix.image` оболочка использует этот путь напрямую, а выбор
других обоев в ней отключён. Если изображения нет, остаётся штатное управление
обоями Caelestia. CLI-темизация сторонних приложений отключена: ими владеет Stylix.

После **отдельно разрешённого применения** нужен выход и повторный вход в
сессию. Пути схемы и обоев передаются через окружение Hyprland и относятся к
конкретному поколению. Перезапуск только shell не гарантирует обновление или
удаление старых переменных. Мгновенное применение темы не обещается.

### SDDM

`profiles/workstation.nix` подключает `core/sddm.nix` вместо `core/ly.nix`.
Локальная Qt6-тема находится в `core/sddm-theme/`; `theme.conf` генерируется
из системного Stylix. В закреплённом Stylix готового SDDM target нет.
Тема содержит часы, дату, выбор пользователя и сессии, пароль, ошибки входа,
аватар с резервным изображением и кнопки питания. Прозрачность карточки
ограничена снизу ради читаемости. Сессия по умолчанию — `hyprland-uwsm`.

Greeter работает через Wayland; параметры дисков, загрузчика, пользователей
и SSH не меняются. U2F сохраняет прежний режим `sufficient` перед штатной
парольной проверкой SDDM. Это проверено по сгенерированному PAM-стеку,
но не заменяет проверки реального входа с паролем и ключом.

Для декларативного возврата к Ly замените импорт `../core/sddm.nix` на
`../core/ly.nix` в `profiles/workstation.nix`. Не подключайте оба одновременно.
Предыдущее поколение NixOS также остаётся способом восстановления.
Переключение display manager требует отдельного разрешения и завершения сеанса;
в ходе разработки оно не выполняется.

## Стабильность сессии и интерфейс Caelestia

Итерация от 13 ноября 2026 года: ветка `fix/celestia-session-stability-ux`,
база `8993e92`. К началу диагностики на машине уже работали Caelestia,
SDDM 0.21.0, Hyprland 0.55.3 и UWSM 0.26.4. Эта итерация не применяет новую
конфигурацию и не завершает активную сессию.

### Что происходило при Logout

В загрузке `25a898e2cb314043ae37dd016e659a58` 13 ноября в 00:52:20 МСК
завершение `session-2.scope` послало SIGTERM одновременно `sddm-helper`,
обёртке UWSM и ожидающему процессу `systemctl`. SDDM зарегистрировал
`Process crashed` и завершение helper с кодом 1. Затем UWSM остановил
порталы и Hyprland; через 0,53 секунды login-сессия была удалена, но greeter
не появился. В 00:53:38 logind зарегистрировал вход через TTY. Этот эпизод
подтверждает потерю графического входа после завершения сессии, а не зависание
всего ядра; coredump или GPU reset в соответствующем интервале не найден.

Штатная команда `logout` закреплённой Caelestia вызывает
`org.freedesktop.login1.Session.Terminate`, то есть завершает весь login scope
вместе с помощником SDDM. Это соответствует последовательности в журнале.
Вместо неё `session.commands.logout` получает короткую команду из
`home/zerokqx/hyprland/binds.nix`, общую с двумя сочетаниями выхода.
Она проверяет активный UWSM и совпадение `HYPRLAND_INSTANCE_SIGNATURE` с
окружением менеджера пользователя, затем вызывает `uwsm stop`. Так управление
остановкой остаётся у менеджера графической сессии. Для отдельно запущенного
Hyprland остаётся `hyprctl dispatch exit`. При отсутствии сигнатуры или ошибке
чтения состояния команда завершается с ошибкой, не пытаясь угадать сессию.

Это соответствует [механизму остановки UWSM](https://github.com/Vladimir-csp/uwsm/blob/master/README.md#how-to-stop).
Не добавлены принудительное завершение пользователя, перезапуск SDDM,
произвольные задержки или изменения таймаутов. Реальный возврат к greeter
после исправления требует отдельной проверки с разрешённым Logout;
успешная сборка этого не доказывает.

### Где задерживается SDDM

Журналы двух загрузок одной исходной темы дают следующие интервалы:

| Интервал                           | Загрузка 00:47 | Загрузка 00:54 |
| ---------------------------------- | -------------: | -------------: |
| Старт службы → загрузка QML        |        2,057 с |        4,516 с |
| Загрузка QML → первое окно greeter |        0,126 с |        0,880 с |
| Старт службы → первое окно greeter |        2,183 с |        5,396 с |

В медленной загрузке основная задержка возникла до QML, при подготовке
Wayland greeter/Weston и графического стека. Это ещё не доказательство конкретного
дефекта драйвера: время отличается между загрузками. `graphical.target` также
ждёт NetworkManager и Docker, но greeter появляется независимо от завершения
всей этой цепочки. Время PAM после отправки пароля — отдельный интервал,
его нельзя приписывать загрузке темы. Backend, драйвер, PAM и необходимые
systemd-службы ради сокращения этих чисел не менялись.

В самой теме исправлены циклические привязки Qt palette: значения её полей
теперь берутся из независимых свойств Stylix, а не читаются обратно из той же
изменяемой группы `palette`. Все цвета и шрифты по-прежнему генерируются в
`core/sddm.nix`; второго источника палитры нет.

Экран входа теперь содержит компактную центральную форму, часы с двумя
акцентами, округлые поля и кнопки в стиле Caelestia. Сохранены ввод имени,
выбор пользователя и сессии, пароль, ошибки входа, выключение и перезагрузка.
На низком разрешении содержимое прокручивается; изображение загружается
асинхронно с ограничением размера по экрану. Тяжёлых blur-эффектов нет.

В 15 парных изолированных запусках старой и новой темы на одном Qt greeter,

### Раскладка без всплывающей подсказки

Подсказку создавал встроенный toast Caelestia по событию Hyprland
`activelayout`. В `home/zerokqx/desktop.nix` отключён только
`utilities.toasts.kbLayoutChanged`; остальные уведомления сохранены.
В массиве `bar.statusIcons` включён штатный `kbLayout`, остальные индикаторы
сохраняют прежние значения.

В этой версии он показывает XKB-коды `us` / `ru`. Это встроенный индикатор
английской и русской раскладки, без отдельного QML-патча, daemon или polling.
При запуске и событиях раскладки Caelestia читает `j/devices` и выбирает
основную клавиатуру; состояние не вычисляется по нажатой комбинации клавиш.
Ограничение upstream: отключение клавиатуры само по себе может не породить
`activelayout`; тогда состояние обновится при следующем событии раскладки
или запуске оболочки. Это не индикатор всех устройств одновременно.

## Процедурный liquid-фон

`scripts/generate-liquid.py` — самостоятельный генератор MP4, а не часть
темы SDDM. Он рендерит GLSL-сцену с периодическим временем и кодирует заранее
готовый H.264/yuv420p ролик. Генерация выполняется только вручную в отдельном
`liquid-background` devShell; Python, EGL, FFmpeg и shader не попадают в
системный closure и не запускаются при входе в систему.

Пример ручной палитры:

```sh
nix develop .#liquid-background -c python scripts/generate-liquid.py \
  --colors '#101018,#292044,#63518f,#a18ac8' \
  --duration 12 --fps 30 --width 1920 --height 1080 \
  --speed 1 --intensity 1 --grain 0.12 --softness 0.6 --seed 42 \
  --output /абсолютный/путь/liquid-background.mp4 | tee /абсолютный/путь/liquid-background.json
```

Для палитры текущего NixOS-хоста замените `--colors …` на `--stylix desktop`.
Это извлекает Base16 из Nix evaluation; цвета вручную не копируются. Режимы
взаимоисключающие. Допустимы 2–6 HEX-цветов, а одинаковые аргументы и seed
воспроизводят тот же набор GLSL-кадров при закреплённых версиях окружения.
Сохраняйте MP4, JSON и preview вне Git, например в
`/home/zerok/.codex/visualizations/`.

Период цикла задаётся `duration`; `speed` меняет траекторию в замкнутом
пространстве, не меняя длительность. Перед использованием проверяйте поток
через FFprobe, декодирование кадров и границу первого/последнего кадров, а
также просматривайте ролик глазами. Небольшая численная разница кадров не
доказывает, что движение на границе воспринимается бесшовным.

Для инструкций агентам есть [skill desktop-backgrounds](.agents/skills/desktop-backgrounds/SKILL.md).
Фон подключён декларативно в `core/sddm.nix`. Пакет
`pkgs/liquid-background.nix` заранее генерирует MP4 и статичный первый кадр
через программный OpenGL при сборке Nix; генератор не запускается при входе.
Палитра по умолчанию берётся из Stylix. `znix.sddm.liquid.colors` принимает
2–6 цветов `#RRGGBB` от тёмного к светлому, `null` сохраняет палитру Stylix.
Отключение: `znix.sddm.liquid.enable = false;`.
Qt Multimedia добавляется только при включённом фоне. Пока видео загружается
или при ошибке декодера тема показывает статичный первый кадр.

Проверить сборку видео без применения системы:

```sh
nix build --no-link --no-update-lock-file \
  .#nixosConfigurations.desktop.config.system.build.sddmLiquidBackground
```

Подключение сохранено в конфигурации; реальный SDDM этой операцией не
перезапускается. Плавность повторного воспроизведения и влияние на время
появления greeter требуют отдельной проверки на экране входа.

Тестовый ролик создан с палитрой Stylix `desktop`: base00/base02/base0E/base0D/base0C
дали `#1a1b26`, `#2f3549`, `#bb9af7`, `#2ac3de`, `#b4f9f8`. Он находится вне
репозитория в `/home/zerok/.codex/visualizations/liquid-background/` вместе с
`preview.gif`, `still.png`, `parameters.json` и `verification.json`. Ролик —
1920×1080, 30 FPS, 360 кадров, 12 секунд, H.264/yuv420p, 5,13 МБ. Он создан
на AMD Radeon RX 6600 за 6,71 секунды. Повторная генерация с теми же аргументами
на той же GPU и в закреплённом окружении
дала тот же SHA-256 `f097ef768ae9d8652a51ceca19824474b40c0d510ba15f82e0316fbfb50330c0`.
Проверка FFprobe и декодирование всех 360 кадров
прошли. RMS разницы на шве — 0,831 при медиане соседних кадров 0,719; это
согласуется с периодической параметризацией, но выбор всё ещё должен оценить
человек по preview до интеграции.

### Металлический вариант

## Панель истории буфера

Буфер встроен в Caelestia как нижняя панель: он использует общую жидкую
поверхность оболочки, её анимации, поле поиска, цвета и шрифты. Отдельное окно
Quickshell заменено компонентом `home/zerokqx/clipboard/ClipboardDrawer.qml`.
Патч `caelestia.patch` подключает его к родным панелям; пакет собирается в
`home/zerokqx/desktop.nix`. При отключении Stylix буфер сохраняется и использует
текущую тему Caelestia.

Super+V и Super+Shift+V вызывают `caelestia-shell ipc call drawers toggle clipboard`.
Повторное нажатие закрывает панель. При открытии виден компактный список.
Клик по карточке или выбор стрелками раскрывает справа подробное превью;
наведение само по себе его не открывает. Enter или кнопка копирования копирует
оригинал и закрывает панель, Escape закрывает без копирования. Вставка остаётся
обычной Ctrl+V. Длинный текст в карточках сокращается; справа доступно
прокручиваемое текстовое превью и увеличенное изображение. Превью текста
ограничено 65 536 символами, копирование сохраняет весь оригинал. На узких
экранах превью заменяет список с возможностью вернуться назад.
Видео поддерживается для одиночной локальной ссылки `file://` или абсолютного
пути к существующему файлу (в том числе после копирования в Nautilus):
воспроизведение запускается вручную, без звука. Интернет-ссылки автоматически
не открываются и не загружаются.
Изменения вступают в силу после отдельно разрешённого применения конфигурации
и запуска нового пакета оболочки.

Историю по-прежнему собирает существующий `wl-paste --watch cliphist store`;
настройки и меню DMS не меняются. Миниатюры передаются в памяти без временных
файлов, текст отображается без HTML. После закрывающей анимации содержимое
панели выгружается; следующее открытие заново читает историю.
Поиск ограничен первыми 360 символами превью cliphist. Для проверки используются
только отдельная тестовая история и изолированный графический сеанс.

Проверка расширяемой панели: пакет Caelestia собран, `workflow` и
`desktop-shells` прошли. Статическая проверка и 32 теста прошли.
В изолированном Wayland-сеансе на экранах 1280×800 и 540×700 проверены
настоящий `Drawers`/`BlobGroup`, выбор кликом и стрелками, расширение
с 540 до 900 пикселей без смещения левого края, перенос и прокрутка текста,
превью PNG, ручное воспроизведение локального видео и копирование исходного
текста без изменения байтов. На узком экране превью заменяет список,
сохраняя доступ к поиску. Полная evaluation хостов в этой доработке
повторно не выполнялась.
Тест использует отдельный вход QML без фоновых служб оболочки. В Sway нет
`HyprlandFocusGrab`, поэтому фокус для ввода задавался кликом; захват фокуса
и переключение мониторов в рабочем Hyprland этим не подтверждены.

### Звуковая панель Caelestia

Значки звука и микрофона включены в `home/zerokqx/desktop.nix`. Панель
использует родной AudioPopout и его жидкую поверхность; отдельный микшер
или второй процесс оболочки не запускается. Наведение на значок открывает
панель с вкладками выхода, микрофона и приложений. Можно выбирать выход и
микрофон, менять их громкость, включать mute и регулировать отдельные
потоки воспроизведения приложений. Ползунки ограничены 100%; во время mute
они отключены. Списки прокручиваются внутри панели.

Пакет собран; `desktop-shells`, статическая проверка и 32 теста прошли.
Конфигурация `desktop` вычислена без применения. В отдельном Sway с
изолированным PipeWire проверены открытие родного popout, вкладки, выбор
выхода и микрофона, mute микрофона и изменение громкости микрофона и
тестового потока приложения. Захват звука не попадает в список воспроизведения.
Рабочая оболочка не перезапускалась; новое меню станет доступно после
отдельного применения конфигурации и запуска нового пакета Caelestia.

сохранены; старые поколения Nix-профиля не очищались.
