# ZNix

Персональная конфигурация NixOS и Home Manager для трёх машин x86_64-linux.
Рабочее окружение: Hyprland, Dank Material Shell, Fish и Nixvim.
Основная версия системы — NixOS 26.05; зависимости закреплены в `flake.lock`.

| Хост flake | Имя системы    | Профили                                                             |
| ---------- | -------------- | ------------------------------------------------------------------- |
| `desktop`  | `nixos-pc`     | workstation + development + personal                                |
| `laptop`   | `nixos-laptop` | workstation + development + personal                                |
| `noop`     | `nixos`        | workstation + development + personal + дополнения Home Manager noop |

`flake.nix` использует flake-parts. Системы и самостоятельные конфигурации
Home Manager явно зарегистрированы в `hosts/default.nix`. Форматирование, среда разработки, VM-тест и проверки определены через
`perSystem` в `flake/`. Отдельных приложений для `nix run` и установщика для
сторонних пользователей нет; Nixvim входит в личную конфигурацию Home Manager.
Каждый хост явно подключает базу, профили и своё оборудование. Общие системные
модули находятся в `core/` и `configs/`, пользовательские настройки — в `home/`,
общие модули Home Manager и политика пакетов — в `lib/`.

## Проверка и сборка

```sh
nix develop -c bash
nix fmt -- flake.nix hosts/default.nix
./scripts/check.sh all
nix flake check --no-build --no-update-lock-file
nix flake check --no-update-lock-file
./scripts/rebuild.sh build desktop
```

Для проверки всей серии изменений укажите `check.sh all --base <коммит>`.
Новые файлы, на которые ссылается flake, добавляйте в Git точными путями после
проверки содержимого. Скрипты пересборки сами ничего не добавляют в индекс.

Общая команда `rebuild` по умолчанию только собирает систему. Команды devenv
`rebuild-desktop`, `rebuild-laptop` и `rebuild-noop` применяют конфигурацию;
варианты `-test` тоже меняют работающую систему. Используйте их осознанно.
Без указания хоста скрипт ищет единственное соответствие текущему имени машины.
Успешная сборка не означает применение конфигурации или проверку оборудования.

## Подключение агентов

Прочитайте [AGENTS.md](AGENTS.md) и
[инструкцию установки skills](.agents/skills/install/SKILL.md), затем выберите среду:

```sh
python3 scripts/install-skills.py --environment codex
python3 scripts/install-skills.py --environment claude
```

Codex читает `.agents/skills` напрямую. Для Claude создаются относительные ссылки
на каждый skill. Повторная установка безопасна и останавливается при конфликте.
Глобальные настройки агентов не меняются.

## Добавление хоста

Создайте модуль в `hosts/<имя>/` с явными imports оборудования, базы и выбранных
профилей. Зарегистрируйте его в `hosts/default.nix` через `nixpkgs.lib.nixosSystem`.
Самостоятельную конфигурацию Home Manager при необходимости добавьте через
локальный `mkHome`. Подробности — в [описании архитектуры](docs/architecture.md).

UUID дисков, параметры возобновления из гибернации и мониторы относятся к
конкретной машине. Для другой архитектуры процессора отдельно проверяйте
совместимость пакетов. Применение конфигурации и разрушительные операции
требуют явного разрешения владельца.

## Nixvim: аудит и оптимизация

Итерация `refactor/nixvim-performance-modernization`, исходная точка `ef9a24e`.
Nixvim остаётся личным модулем Home Manager с явными imports. Публичные
`nix run` outputs не возвращены. `flake.lock`, тема TokyoNight, основные клавиши,
Blink, Snacks и Mini сохранены.

### Что изменилось

- Rust-тесты ищутся запросом Treesitter вместо рекурсивного обхода всех узлов
  из Lua. Результат кешируется до изменения текста. Сворачивание учитывает
  конкретное окно, повторные события и переключение буфера до отложенного вызова.
  Распознаются модули `test/tests`, точный `#[cfg(test)]` и атрибуты
  `test/rstest/test_case/quickcheck/proptest`, включая квалифицированные имена.
  Случайные подстроки вроде `#[contest]` больше не считаются тестами.
- Большие буферы дополнительно исключены из миникарты, направляющих,
  Git-декораций и автоматического включения inlay hints. Существующий порог
  Snacks и отключение подсветки/автодополнения сохранены.
- Автосохранение проверяет пригодность буфера до создания таймера и отменяет
  таймер при выгрузке. Запись остаётся синхронной, задержки не менялись.
  Исправлена гонка восстановления раскладки при быстрых переходах Insert mode.
- Настройки vtsls больше не перекрывают подключение `@vue/typescript-plugin`.
  Lua, JSON и YAML используют структуру настроек закреплённого Nixvim.
  Удалены 18 повторных объявлений пакетов LSP и неиспользуемая настройка
  Blink buffer source. Сами серверы предоставляет Nixvim; это не удаление LSP.
- Treesitter использует поддерживаемые параметры `highlight`/`indent` и явный
  набор из 60 грамматик вместо 326. Включены языки конфигурации, запросов и
  вложенных фрагментов. Произвольный язык внутри Markdown может потребовать
  добавления грамматики в `config.nix`; сам Markdown продолжает работать.
- Gitsigns использует `nav_hunk`; в diff-окне `]c/[c` сохраняют нативные переходы.
  Справка по клавишам имеет один обработчик и берётся из runtime сборки.
  Цветные иконки таблайна обрабатываются одним проходом по видимым вкладкам.
- Добавлены изолированный benchmark, функциональные Lua-проверки и
  [skill Nixvim](.agents/skills/nixvim/SKILL.md). Установщик распознаёт восемь skills.

### Измерения

Обе сборки используют один `neovim-unwrapped-0.12.4`, одинаковые fixtures и
семь повторов. Терминальные измерения выполнены в PTY 100×32 с ответами на
запросы терминала. `cold` означает новые HOME/XDG-каталоги; кеш ОС не очищался.
Прогрев перед серией `warm` исключён из результата. В таблице медианы.

| Сценарий                                 |            До |         После |
| ---------------------------------------- | ------------: | ------------: |
| Headless, cold                           |      88,70 мс |      91,16 мс |
| Headless, warm                           |      76,05 мс |      73,99 мс |
| Терминал, cold                           |      96,71 мс |      89,33 мс |
| Терминал, warm                           |      78,74 мс |      72,04 мс |
| Rust-тесты: первый вызов после изменения |      43,30 мс |      18,36 мс |
| Rust-тесты: повторный вызов              |      39,31 мс |       0,22 мс |
| Открытие и перерисовка небольшого Rust   |     130,28 мс |     126,94 мс |
| Открытие Rust, 1 500 987 байт            |     114,99 мс |     115,67 мс |
| Открытие небольшого JSON                 |      18,05 мс |      15,30 мс |
| Открытие JSON, 2 371 338 байт            |      21,80 мс |      20,94 мс |
| Переключение буфера и перерисовка        |       2,32 мс |       2,30 мс |
| RSS после сценария открытия файлов       |    42 572 КиБ |    42 756 КиБ |
| Полное замыкание Nix, NAR-байты          | 6 378 431 120 | 6 167 189 992 |

Первое сворачивание ускорилось на 57,6%, повторное — на 99,4%.
Диапазоны первого вызова: 31,40–45,98 → 14,80–21,06 мс; повторного:
38,44–42,75 → 0,16–0,31 мс. Здесь эффект превышает разброс.
Диапазоны прогретого терминального запуска пересекаются:
73,73–92,51 → 69,60–81,54 мс. Считать это доказательством устойчивого
ускорения запуска нельзя. Память и открытие больших файлов практически
не изменились. Первый Rust-файл оплачивает начальную загрузку подсистем;
сравнение маленького и большого файла внутри одной серии не характеризует
масштабирование. Отложенное автосворачивание не входит в `edit+redraw`;
оно проверяется отдельно, ручное сворачивание измеряется в свежем процессе.

Замыкание уменьшилось на 211 241 128 байт (3,3%). Его основную часть по-прежнему
занимают языковые серверы и инструменты. Это размер NAR всех зависимостей,
а не трафик загрузки и не место, освобождённое на диске. Сборка использовала
доступные substitutes и локально собрала конфигурацию, обёртку и набор queries.
Время сборки с нуля и cache hit rate не измерялись. Изменение доверенных кешей
или объединение nixpkgs Nixvim с системным input для этой задачи не требуется.

neo-tree, Neogit, Diffview, Noice, lualine и bufferline дублировало бы имеющиеся
сценарии либо добавляло новые без запроса. Netrw и обычный `:terminal` не

комментирование уже используются. Byte compilation и Lua loader сохранены.

ждать `timeoutlen`; привычная клавиша не менялась без отдельного решения.

### Проверки и воспроизведение

Команды сборки, изоляции HOME/XDG и запуска проверок описаны в
[skill Nixvim](.agents/skills/nixvim/SKILL.md).
Скрипт `scripts/benchmark-nixvim.py` принимает путь к собранному `bin/nvim`,
новый каталог результатов и необязательный `--runs`. Он сохраняет сырые
traces, журналы, fixtures и `results.json`. Не запускайте параллельно с ним
сборки или языковые серверы другого теста.

Реальный LSP проверяется отдельно от startup. CSSLS должен возвращать `color`
со snippet capability, Ruff — диагностику и отключённый hover, Pyright —
подключение, Vue/vtsls — подключение с `@vue/typescript-plugin`. Остальные
серверы требуют отдельных проектов и не считаются проверенными этим тестом.
Замеры PTY не измеряют задержку физических клавиш, GPU/терминальный рендеринг,
completion на большом рабочем проекте или производительность всех серверов.
Применение Home Manager/NixOS и проверка реальной раскладки Hyprland не выполняются;
гонка раскладки проверяется с подменённым вызовом процесса.

Подтверждены сборка редактора и `programs.nixvim.build.test`, все три
Lua-сценария, 22 теста инструментов, форматирование/ShellCheck и evaluation
трёх NixOS-хостов и трёх Home Manager outputs. Независимая проверка подтвердила
сохранение таблайна, справки, Conform defaults, переходов Git/diff, JSONC и
возврата к обычному Rust-буферу после большого файла. Полные системы не
собирались и не запускались. Сохраняется прежнее предупреждение Home Manager
о `nixpkgs.config/overlays` при `useGlobalPkgs`; оно не относится к Nixvim и
требует отдельной правки общего управления пакетами.
