# Процедурные фоны desktop

`scripts/generate-liquid.py` создаёт заранее закодированный MP4 из GLSL-кадров.
Он не является runtime-службой и не должен вызываться из activation, SDDM
или login hooks. Ручная среда генерации — `devShells.liquid-background`.
`pkgs/liquid-background.nix` запускает генератор только при сборке Nix через
llvmpipe и создаёт готовые MP4 и PNG; инструменты генерации — build inputs.

Текущий shader создаёт металлические текучие ленты: нормали округлого сечения
управляют отражениями световых полос. Первый цвет палитры задаёт тёмный фон,
промежуточные — оттенки отражений, последний — светлый оттенок бликов.
Для выраженного хрома передавайте палитру от тёмного к светлому. `softness`
регулирует ширину отражённых полос; отдельный цвет металла не зашит в GLSL.

Сначала создайте и проверьте артефакт отдельно от темы:

```sh
nix develop .#liquid-background -c python scripts/generate-liquid.py \
  --stylix desktop --duration 12 --fps 30 --width 1920 --height 1080 \
  --speed 1 --intensity 1 --grain 0.12 --softness 0.6 --seed 42 \
  --output /абсолютный/путь/liquid.mp4
```

`--stylix <host>` получает Base16 через Nix evaluation для зарегистрированного
хоста. Ручный режим заменяет его: `--colors '#101018,#292044,#63518f,#a18ac8'`.
Передавайте 2–6 шестнадцатеричных цветов с `#`; одновременно режимы не
используйте. Одинаковые аргументы и seed воспроизводят одни и те же GLSL-кадры
при закреплённых версиях окружения. `speed` меняет движение по замкнутой
траектории, а не длительность цикла.

Сохраняйте MP4, preview, первый кадр и JSON-отчёт вне Git, например в
`/home/zerok/.codex/visualizations/`. Не добавляйте бинарное видео в repository
и не создавайте assets-каталог без отдельного решения. Проверяйте ffprobe,
декодирование каждого кадра и границу цикла: генератор должен сравнивать
первый/последний кадр и скорость движения около границы. Численная проверка
сама по себе не заменяет визуальный просмотр ролика.

Декларативное подключение находится в `core/sddm.nix`:
`znix.sddm.liquid.enable` включает видео (по умолчанию true), `colors = null`
берёт палитру Stylix; явный список принимает 2–6 цветов `#RRGGBB`.
При отключённом Stylix или видео Qt Multimedia этим модулем не добавляется.
`core/sddm-theme/VideoBackground.qml` загружается через Loader, а статичный
первый кадр остаётся под видео на время загрузки или при ошибке декодера.

```sh
nix build --no-link --no-update-lock-file \
  .#nixosConfigurations.desktop.config.system.build.sddmLiquidBackground
```

Проверяйте отдельно сборку артефакта, QML-декодер и реальный экран входа.
Поддержка loop в Qt API не доказывает отсутствие видимого кадра на границе
именно у SDDM. Изменение палитры пересобирает артефакт, а не запускает генератор
при входе. Не меняйте backend greeter и не перезапускайте SDDM в рабочем сеансе;
активация системы требует отдельного разрешения владельца.
