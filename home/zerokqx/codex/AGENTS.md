# Общие правила

Пиши минимальный код, который полностью решает поставленную задачу и соответствует существующему проекту.

- **KISS:** выбирай самое простое понятное решение. Не добавляй уровни абстракции, настройки, зависимости и обобщения без конкретной необходимости.
- **YAGNI:** не реализуй предполагаемые будущие требования. Меняй только то, что нужно для текущей задачи.
- **DRY:** убирай дублирование, когда повторяется одна и та же логика и общий код действительно упрощает поддержку. Не создавай абстракцию ради единственного использования или совпадающих строк.
- **Бритва Оккама:** среди решений, одинаково хорошо решающих задачу, предпочитай решение с меньшим числом сущностей, состояний, файлов и специальных случаев.
- Сохраняй существующие соглашения и поведение проекта. Не переписывай соседний код без необходимости.
- Делай код лаконичным, но оставляй ясные имена и структуру. Не сокращай код так, чтобы его стало труднее читать.
- Перед добавлением helper, компонента, хука или нового файла проверь, нельзя ли решить задачу проще в существующем месте.

## Делегирование

Используй настроенные роли из `~/.codex/agents/` автоматически, когда задача требует работы с кодовой базой.

Перед делегированием оцени размер и независимость работы. Не запускай сабагента для самодостаточного ответа, одного известного файла, одной команды или простой локальной правки: в таких случаях дополнительный контекст и итоговая сводка стоят дороже пользы.

Выбирай наименее затратную подходящую роль. Модель и уровень рассуждений роли определяются в `~/.codex/agents/*.toml`: для ограниченного поиска и механических задач используй роли на Luna; более сильную модель — только если необходимы связанное рассуждение, реализация или проверка с существенным риском.

- Для исследования структуры, поиска владельца кода, чтения нескольких файлов и простых вопросов о проекте сначала поручай работу `fast_scanner`. Он только читает и возвращает краткие результаты; после этого используй их в основной задаче.
- Для чёткой локальной правки после исследования поручай реализацию `routine_worker`.
- Для обычной многошаговой реализации, требующей правок и проверки, но без архитектурной неопределённости, поручай работу `terra_worker`.
- Для неоднозначных багов, многофайловых изменений, рефакторинга, архитектурных решений и задач с существенным риском поручай работу `deep_worker`.
- Запускай роли параллельно только для независимых частей задачи. Не создавай сабагента для самодостаточного ответа, одношаговой команды или правки, когда нужный файл уже дан пользователем.
- Не дублируй исследование между ролями и не дроби последовательную задачу на несколько сабагентов. Передавай каждому только ограниченную цель, нужные файлы и ожидаемый формат краткого результата.
- После работы сабагента основной агент проверяет вывод в достаточной степени, принимает итоговое решение и объединяет результаты; не воспринимает сводку как доказательство без проверки, когда цена ошибки заметна.
- Вложенное делегирование допускается только от `terra_worker` и `deep_worker` к одному или нескольким `fast_scanner` для независимого узкого исследования. Глубина дерева — не более двух уровней.
- `fast_scanner` и `routine_worker` не запускают сабагентов. Вложенный `fast_scanner` не запускает никого.
- Основной агент принимает итоговое решение, объединяет результаты и сообщает пользователю проверенный итог.
