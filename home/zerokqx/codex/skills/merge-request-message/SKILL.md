# Описание Merge Request

Подготовь готовый к вставке текст для ревьюера, который не читал чат. Объясни проблему, результат и существенные решения, а не пересказывай историю работы или список коммитов.

## Основание

- Используй указанную пользователем задачу, MR или диапазон коммитов. Для локальной ветки проверь status и итоговый diff относительно целевой ветки через merge-base. Цель определи из MR или контекста; если она неизвестна и влияет на состав изменений, уточни её, не подставляй main автоматически.
- Описывай итоговые изменения всего MR, а не только последний коммит. Незакоммиченные правки не выдавай за включённые в MR. Для черновика будущего MR учитывай их, если пользователь включил их в объём.
- Проверь существенные утверждения по коду и имеющимся результатам проверок. Сам запрос на текст не требует повторно запускать всю проверку проекта. Не выдумывай тесты, ссылки, причины решений, успешный CI или факт деплоя.

## Содержание

- Предложи короткий заголовок по конечному результату. Conventional Commit в заголовке не обязателен, если этого не требуют пользователь или правила репозитория.
- Начни описание с того, какую проблему решает MR и как теперь работает сценарий. Если полезно, приведи конкретный пример «до → после».
- Дальше включи только значимые изменения и причины неочевидных решений. Технические детали добавляй, когда они помогают ревью: изменение контракта, миграция, общий механизм, совместимость.
- Укажи подтверждённые проверки и существенные непроверенные области. Отделяй локальные тесты, браузерную проверку, CI и выпуск.
- Для крупного diff можно кратко подсказать, с каких файлов начать ревью, и отметить сгенерированные файлы или ассеты. Не превращай описание в полный перечень файлов.
- Соблюдай шаблон MR репозитория, если он есть. Иначе масштабируй текст по задаче: для маленькой правки достаточно пары предложений и результатов проверки. Не добавляй пустые разделы, рекламные оценки и детали переписки.

## Выдача и границы

Выдай заголовок и описание в готовом для копирования виде, используя доступный формат writing block. По умолчанию только подготовь текст в чате. Не создавай и не редактируй MR, не отправляй сообщения, не делай commit/push/merge без отдельного поручения. Не создавай файлы отчёта ради текста MR.
