# Правила React

Цель — решать задачу простым React-кодом без лишнего состояния, эффектов и абстракций.

## Хуки и состояние

- Не используй `useState`, если значение можно получить из props, текущих данных или обычного вычисления при рендере. Храни только минимальное состояние, которое нельзя вывести из других значений.
- Не используй `useEffect` для вычисления производных данных, обработки действий пользователя или синхронизации состояния React с самим собой. Выполняй вычисление при рендере, а реакцию на действие — в обработчике события.
- Используй `useEffect` только для синхронизации с внешней системой: подписками, таймерами, DOM API или сетевым взаимодействием, которому действительно нужен жизненный цикл. Корректно очищай подписки и ресурсы.
- Не добавляй `useMemo` и `useCallback` по умолчанию. Используй их при подтверждённой проблеме производительности или когда стабильная ссылка нужна конкретному API.
- Не создавай пользовательский хук для одного-двух вызовов без повторно используемого поведения или ясного выигрыша в читаемости.
- Соблюдай правила вызова хуков; не вызывай хуки условно, в циклах или вложенных функциях.

## Компоненты

- Не превращай компонент в god-object: разделяй его, когда у частей есть самостоятельная ответственность, поведение или повторное использование.
- Выноси связную часть интерфейса или поведения в компонент, когда это упрощает родительский компонент. Не дроби разметку на компоненты ради каждого элемента или строки.
- Держи состояние рядом с компонентом, который им владеет; поднимай его только к общему владельцу, которому оно действительно нужно.
- Не добавляй универсальные компоненты, prop-режимы и конфигурируемые оболочки до появления нескольких реальных случаев использования.
- Предпочитай явные props и прямой поток данных. Не вводи контексты, глобальное состояние и новые библиотеки для локальной задачи.

## Изменения

- Следуй структуре, соглашениям и библиотекам проекта.
- Не создавай отдельный файл или слой, если существующая структура не выигрывает от этого.
- При рефакторинге сохраняй поведение и ограничивай изменение областью задачи.
