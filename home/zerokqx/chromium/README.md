# Chromium и DevTools

`default.nix` сохраняет настройки браузера, Widevine, расширения и закладки,
собирает `frontend/` и передаёт Chromium
`--custom-devtools-frontend=file:///nix/store/…`. Frontend также доступен по
`~/.local/share/chromium/devtools`.

Это полный frontend Chromium DevTools с локально изменённым оформлением.
`frontend/build.py` извлекает все ресурсы DevTools из **той же сборки Chromium**,
которая выбрана в Home Manager. Затем он применяет стили и SVG. Полная копия
upstream не хранится в Git; Elements, Console, Network, Sources, Performance
и остальные инструменты берутся из пакета браузера. Пересобирать Chromium,
поднимать сервер или включать remote debugging для обычной работы не нужно.

## Оформление

- `frontend/design.css` задаёт размеры, типографику, состояния и поверхности
  Material Design 3. Горизонтальные вкладки имеют высоту 48px и индикатор 3px,
  стандартные кнопки — 40px, outlined-поля — 56px и радиус 4px. Диалоги имеют
  радиус 28px, внутренние отступы 24px и заголовок 24/32px. Ширина обычного
  диалога ограничена 560px; длинное содержимое прокручивается отдельно от действий.
  Используются стандартные кривые движения M3; `prefers-reduced-motion`
  отключает добавленные анимации. Прежние вкладки-капсулы и произвольное
  масштабирование при нажатии убраны.
- `frontend/tokens.css` связывает цвета интерфейса и синтаксиса с Base16 Stylix.
  Шрифты и палитру генерирует `default.nix` из текущей конфигурации.
- `frontend/styles.json` сопоставляет исходные стили компонентов с локальными
  файлами в `frontend/styles/`. Стили добавляются непосредственно в бандлы,
  поэтому применяются и внутри Shadow DOM. Размеры виртуализированных строк
  Network, Console и редактора сохранены.
- `frontend/icons.json` заменяет 58 иконок на SVG из `lucide-static` 1.73.0.
  Используемые SVG и лицензия находятся в `frontend/icons/`.
- Переключение темы Stylix требует новой сборки/активации Home Manager и полного
  перезапуска Chromium. Обычный выбор темы в DevTools не меняет палитру Stylix.
  Режим системных контрастных цветов сохраняет правила доступности upstream.

Параметры компонентов сверены с официальной реализацией Google Material Web:
[вкладки](https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-comp-primary-navigation-tab.scss),
[кнопки](https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-comp-filled-button.scss),
[поля](https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-comp-outlined-text-field.scss),
[диалоги](https://github.com/material-components/material-web/blob/main/dialog/internal/_dialog.scss).
Компактные штатные панели инструментов, вертикальные списки, виртуализированные
таблицы и редакторы кода сохраняют размеры Chromium. Это специализированные
инструменты DevTools; их геометрия не заменяется геометрией обычных M3-форм.

## Storage

В Application → Local Storage или Session Storage нажмите запись либо выберите
её клавиатурой и нажмите Enter. Откроется модальное окно с именем ключа и
редактором значения. JSON автоматически форматируется, подсвечивается и
сворачивается по блокам. Кнопка Format JSON форматирует текущий текст;
сохранение некорректного JSON блокируется. Для произвольной строки выберите String.

Save сохраняет правки; Cancel и Escape закрывают окно без записи. Простое
открытие или переименование не меняет исходное представление JSON. Форматирование
сохраняет большие числа, порядок и повторяющиеся ключи. Существующий ключ
нельзя затереть переименованием. Если запись изменилась во время редактирования,
редактор сообщает об этом. Переименование состоит из записи нового ключа и
удаления старого: протокол не предоставляет атомарной операции; при ошибке
удаления обе записи остаются, и окно предлагает их проверить.

## CSS Environment

Откройте вкладку **CSS Environment** через меню дополнительных вкладок или
команду **Show CSS Environment** (`Ctrl+Shift+P`). **Add variable** открывает
модалку с полями Key и Value. Выбор строки открывает ту же модалку для изменения
имени, значения или удаления подмены. Например:

| Key                          | Value               |
| ---------------------------- | ------------------- |
| `safe-area-inset-top`        | `59px`              |
| `viewport-segment-width 0 0` | `390px`             |
| `app-header-height`          | `calc(48px + 16px)` |
| `app-accent`                 | `#7aa2f7`           |

Имена чувствительны к регистру; индексы задаются через пробел. Значение — CSS,
а не JSON. **Save** подставляет значение в соответствующие вызовы `env()`
инспектируемой страницы. **Remove** и **Remove all overrides** восстанавливают
исходные вызовы. Открытие модалки и Cancel не меняют страницу.

Это подмена CSS, выбранная для работы без пересборки Chromium. Она не создаёт
настоящие UA environment variables: CSS, создаваемый страницей позже, не
получает значение автоматически. **Reapply** повторяет подмену после reload,
навигации и динамических изменений. Настройки хранятся только в текущем DevTools.
Уже изменённый CSS остаётся после закрытия DevTools до reload; для отката без
перезагрузки удалите подмены перед закрытием.
Поддерживаются доступные через CDP таблицы стилей, в том числе внешние, и
inline-стили основного документа и открытых Shadow DOM. Отдельные OOPIF-targets,
inline-стили внутри iframe и закрытых Shadow DOM не охвачены.

Редактор сохраняет исходный CSS. Если страница успела изменить тот же источник,
он не перезаписывается и показывается число конфликтов. При конфликте reload
убирает оставшиеся подстановки; затем можно выполнить Reapply. Постоянных
наблюдателей за DOM, подмен JS-прототипов и обхода страницы на каждом кадре нет.

## Производительность

Дополнительные панели и редактор загружаются по требованию. Storage использует
уже поставляемый Chromium CodeMirror с виртуализацией строк; при закрытии
редактор уничтожается вместе с обработчиками. JSON не разбирается на каждом
нажатии клавиши, а автоматическое форматирование ограничено 1 048 576 символами исходного
текста и результата. Более крупное значение остаётся доступным для редактирования.
Движение полей и диалогов использует transform и opacity; постоянных таймеров,
наблюдателей за всем DOM и размытия фона нет. CSS Environment обходит стили
только по явному действию, читая CSS через CDP небольшими пакетами.
Виртуализация штатных панелей сохранена.

Отключить только палитру Stylix, оставив скругления и Lucide:

```nix
stylix.targets.chromium-devtools.enable = false;
```

Вернуть встроенный DevTools:

```nix
programs.chromium.devtools.enable = false;
```

## Проверка и обновления

```sh
nix build --no-link --print-out-paths --no-update-lock-file \
  '.#homeConfigurations.zerokqx.config.xdg.dataFile."chromium/devtools".source'
nix build .#checks.x86_64-linux.chromium-devtools --no-link --no-update-lock-file
nix develop -c ./scripts/check.sh all
```

Сборка рассчитана на текущий Nixpkgs Chromium для Linux x86_64: ELF с таблицей
`kDevtoolsResources` и DataPack v5. При изменении структуры бинарника, удалении
иконки, маркера CSS, конструктора Storage или точки регистрации панели сборка
завершится с ошибкой. После обновления Chromium
нужно проверить эти точки интеграции и запуск панелей в браузере.

Для локального просмотра без активации можно запустить Chromium с отдельным
временным профилем, передав `--custom-devtools-frontend=file://<путь-сборки>`
и `--user-data-dir=<временный-каталог>`. Так существующий процесс браузера
не перехватит запуск без нового флага. Открыть DevTools: `F12`.

Сборка и проверки не применяют конфигурацию системы или Home Manager.
